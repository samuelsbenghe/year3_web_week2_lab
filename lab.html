A4. Build the Starter API

Create main.py inside ~/web-lab2.

The department reverse proxy forwards paths starting with /usr/SERVER_ID/ to your VM without stripping the prefix. FastAPI should treat /usr/SERVER_ID as the proxy’s root_path, rather than mounting the same router twice. This also ensures that FastAPI generates the Swagger UI and OpenAPI documentation URLs correctly.

cat << 'EOF' > main.py
from fastapi import FastAPI, APIRouter

# REPLACE 551 WITH YOUR ACTUAL SERVER ID
SERVER_ID = "551"

app = FastAPI(
    root_path=f"/usr/{SERVER_ID}"
)

router = APIRouter()

@router.get("/")
def read_root():
    return {
        "message": "hello",
        "status": "online"
    }

@router.get("/about")
def read_about():
    return {
        "module": "Dynamic Web Applications",
        "framework": "FastAPI",
        "architecture": "Decoupled API-First"
    }

app.include_router(router)
EOF

Important: Edit main.py (using nano main.py) and verify SERVER_ID matches your actual number. The root_path must match the /usr/SERVER_ID prefix used by the department reverse proxy.

A5. Run the Server

Start Uvicorn listening on all network interfaces (0.0.0.0) on port 8000:

python3 -m uvicorn main:app --reload --host 0.0.0.0 --port 8000

Troubleshooting: - Address already in use? A previous process is still holding port 8000. Run fuser -k 8000/tcp and retry. - Server taking over your window? That is normal. Keep this window running so you can see live server logs. - To stop the server at any time, press Ctrl + C.

In greet_user, we specified repeat: int = 1.

Navigate to this URL in your browser:

Part C: Understanding Cross-Origin Resource Sharing (CORS)

C1. Triggering a Real CORS Error

Let’s see the browser’s security boundary in action using your browser’s Developer Tools Console on an external website.

  1. Open a new tab in your browser and go to https://www.google.com.
  2. Press F12 (or right-click anywhere on the page -> Inspect) and click the Console tab.
  3. Paste the following JavaScript snippet into the Console and press Enter (replace 551 with your actual server ID if different):
fetch("[https://www.doc.gold.ac.uk/usr/551/about](https://www.doc.gold.ac.uk/usr/551/about)").then(r => r.json()).then(console.log);

You will see an immediate red error in the console:

Access to fetch at '[https://www.doc.gold.ac.uk/usr/551/about](https://www.doc.gold.ac.uk/usr/551/about)' from origin '[https://www.google.com](https://www.google.com)' 
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.

Google’s site attempted to read data from your Goldsmiths server. The browser blocked it.

C2. What is an “Origin”?

An Origin is defined by three components: 1. Protocol (e.g. http:// vs https://) 2. Domain / Host (e.g. google.com vs doc.gold.ac.uk) 3. Port (e.g. :80, :443, :8000)

If any of these three values differ between the web page making the request and the API serving the data, the request is Cross-Origin.

By default, the browser’s Same-Origin Policy prevents JavaScript running on Origin A from reading responses returned by Origin B.

C3. How CORS Headers Work

CORS is an opt-in mechanism. When JavaScript makes a cross-origin fetch(), the browser automatically appends an Origin header to the HTTP request:

GET /usr/551/about HTTP/1.1
Host: www.doc.gold.ac.uk
Origin: [https://www.google.com](https://www.google.com)

The browser then looks at the server’s HTTP response. If the response does not contain the header Access-Control-Allow-Origin, the browser throws a security error and withholds the data from the script.

To allow access, the server must reply with:

HTTP/1.1 200 OK
Access-Control-Allow-Origin: [https://www.google.com](https://www.google.com)

C4. Practical CORS Configuration Examples in FastAPI

In FastAPI, CORS is managed via CORSMiddleware. Here are common real-world configurations:

Example 1: Allow a specific trusted frontend (e.g., your React/Vue app on localhost)

from fastapi.middleware.cors import CORSMiddleware

origins = [
    "http://localhost:3000",
    "[http://127.0.0.1:3000](http://127.0.0.1:3000)",
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=origins,
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["*"],
)

Example 2: Allow a production domain and staging domain

origins = [
    "[https://myportfolio.com](https://myportfolio.com)",
    "[https://staging.myportfolio.com](https://staging.myportfolio.com)",
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=origins,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

Example 3: Public API (Allow all origins)

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

Part D: Starting Clean — Building a Full CRUD Resource

Now we will build a complete in-memory CRUD (Create, Read, Update, Delete) API from scratch.

D1. Start with a Fresh main.py

In your terminal on the VM, stop the server in Terminal 1 (Ctrl + C).

Delete your previous main.py so you start with a clean slate:

cd ~/web-lab2
rm -f main.py

Create a new main.py with in-memory storage, Pydantic data models, and CORS enabled. This version continues to use root_path=f"/usr/{SERVER_ID}", so the Swagger/OpenAPI documentation works through the department reverse proxy:

cat << 'EOF' > main.py
from fastapi import FastAPI, APIRouter, HTTPException
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel, Field

SERVER_ID = "551"

app = FastAPI(
    root_path=f"/usr/{SERVER_ID}"
)

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

router = APIRouter()


class ItemCreate(BaseModel):
    title: str = Field(min_length=2, max_length=50)
    price: float = Field(gt=0)


items_db = [
    {"id": 1, "title": "Mechanical Keyboard", "price": 89.99},
    {"id": 2, "title": "USB-C Hub", "price": 24.50},
    {"id": 3, "title": "Wireless Mouse", "price": 45.00},
]


@router.get("/")
def read_root():
    return {
        "status": "online",
        "items_count": len(items_db)
    }


@router.get("/items")
def get_all_items():
    return items_db


@router.get("/items/{item_id}")
def get_item(item_id: int):
    for item in items_db:
        if item["id"] == item_id:
            return item

    raise HTTPException(
        status_code=404,
        detail="Item not found"
    )


@router.post("/items", status_code=201)
def create_item(item: ItemCreate):
    new_id = max(
        (i["id"] for i in items_db),
        default=0
    ) + 1

    new_record = {
        "id": new_id,
        "title": item.title,
        "price": item.price
    }

    items_db.append(new_record)

    return new_record


@router.delete("/items/{item_id}")
def delete_item(item_id: int):
    for index, item in enumerate(items_db):
        if item["id"] == item_id:
            removed = items_db.pop(index)

            return {
                "deleted": removed
            }

    raise HTTPException(
        status_code=404,
        detail=f"Item {item_id} not found"
    )


app.include_router(router)
EOF

Appendix: Testing Endpoints from the Command Line (curl)

While the browser is great for GET requests and Swagger docs, developers frequently use curl in the terminal for automated testing and scripting.

From your second terminal window on the VM, you can test endpoints locally:

1. GET requests

# Fetch root
curl [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

# Fetch all items
curl [http://127.0.0.1:8000/items](http://127.0.0.1:8000/items)

# Fetch single item
curl [http://127.0.0.1:8000/items/2](http://127.0.0.1:8000/items/2)

2. POST requests (creating data)

# Add valid item
curl -X POST [http://127.0.0.1:8000/items](http://127.0.0.1:8000/items) \
     -H "Content-Type: application/json" \
     -d '{"title": "Desk Lamp", "price": 19.99}'

# Test validation failure (negative price)
curl -i -X POST [http://127.0.0.1:8000/items](http://127.0.0.1:8000/items) \
     -H "Content-Type: application/json" \
     -d '{"title": "Broken Item", "price": -10.00}'

3. DELETE requests

# Delete item with ID 2
curl -X DELETE [http://127.0.0.1:8000/items/2](http://127.0.0.1:8000/items/2)

# Attempt to delete non-existent item (triggers 404)
curl -i -X DELETE [http://127.0.0.1:8000/items/999](http://127.0.0.1:8000/items/999)
